# 테스트

사이트를 고친 뒤 깨진 곳이 없는지 확인하는 회귀 테스트입니다. 배포에는 필요 없습니다.

```bash
cd tests
npm install
```

## 1. 구문 검사 — `npm run test:parse`

`assets/js/` 와 `worker/` 의 모든 파일을 ES 모듈로 파싱합니다. 브라우저를 띄우지 않아
가장 빠르고, 오타 하나로 사이트가 하얗게 뜨는 사고를 막아줍니다.

## 2. 회원 인증 — `npm run test:auth`

메모리 R2 스텁 위에서 **실제** `shared/auth.js` 와 `shared/r2api.js` 를 돌립니다.
브라우저 없이 서버 쪽 회원 기능만 집중해서 봅니다.

- 가입·중복 가입·대소문자가 다른 같은 이메일
- 로그인 실패 문구가 "계정이 있는지"를 흘리지 않는지
- 세션 쿠키가 HttpOnly · SameSite=Lax · Secure 인지, 위조 쿠키가 거부되는지
- 연속 실패 8회 뒤 잠기는지
- `ADMIN_EMAILS` 로 가입하면 관리자가 되는지
- 회원 명부(`members.json`)가 `/data/*` 로 절대 안 새는지
- 남의 업로드 폴더를 참조한 제출, 남의 제출물 수정·삭제가 막히는지
- 제출자 정보를 서버가 채우는지(클라이언트가 보낸 이름·이메일을 믿지 않는지)
- 비밀번호 변경·관리자 초기화·이용 정지 시 기존 세션 무효화

## 3. R2 모드 통합 — `npm run test:r2`

메모리 R2 스텁 위에서 **실제** `shared/r2api.js` 와 **실제** `store/r2.js` 를 돌립니다.
Cloudflare 계정도 브라우저도 필요 없습니다. 확인하는 것:

- 색인 자동 생성, 한글 제목·파일명 왕복, 업로드 바이트 보존
- etag 조건부 쓰기 — etag 없이 쓰면 428, 낡은 etag 면 409 + 최신본 반환
- 동시 저장 3건이 서로를 덮어쓰지 않고 모두 반영되는지
- 제출물·프로젝트 삭제가 R2 파일까지 연쇄 정리하는지
- 경로 탈출·허용 폴더 밖 키·용량 초과·확장자·낯선 오리진 차단
- 업로드 파일에 `nosniff` 와 sandbox CSP 가 붙는지, SVG 가 인라인으로 열리지 않는지
- 강의자료 다운로드 토큰 — 발급·검증·위조·만료·다른 서명키 거부

## 4. GitHub 모드 통합 — `npm run test:github`

가짜 GitHub API 를 메모리에 만들고, **실제** `worker.js` 와 **실제** `store/github.js` 를
그 사이에 끼워 돌립니다. 브라우저도 네트워크도 필요 없습니다. 확인하는 것:

- 프로젝트·제출물 생성/수정/삭제가 올바른 경로에 커밋되는지
- 한글 제목과 파일명이 base64 왕복에서 깨지지 않는지
- 첨부 바이트가 그대로 보존되는지
- 동시 수정 충돌(409)이 나면 재시도로 복구되는지
- 프로젝트를 지우면 하위 제출물과 첨부까지 정리되는지
- 워커가 경로 탈출·허용 폴더 밖·과대 용량·낯선 출처를 막는지

## 5. 브라우저 종단간 (UI) — `npm run test:browser`

먼저 다른 터미널에서 사이트를 띄웁니다.

```bash
cd .. && python3 -m http.server 8899
```

그 다음 `npm run test:browser`. Chromium 을 띄워 실제 사람이 하는 순서대로
회원가입 → 로그인 → 제출 → 내 제출물 조회·수정 → 관리자(자동 승격) → 프로젝트 개설 →
회원 관리 → 강의자료 → 비밀번호 변경까지 밟고, 폼 검증·404·아코디언·모바일 가로
스크롤·드로어까지 확인합니다. 로그인 전에는 홈·강의자료·내 제출물이 막히는지,
남의 제출물이 목록에 안 보이는지도 함께 봅니다.

이 묶음은 UI 흐름에 집중하려고 **브라우저 저장 모드로 고정**해 돌아갑니다.
그 모드의 회원 기능은 `store/demo-auth.js` 가 흉내내는 **시연용**이라,
진짜 인증 동작은 위 2번과 아래 6번이 봅니다.

## 6. 브라우저 종단간 (R2) — `npm run test:r2-browser`

R2 스텁 위에 사이트와 `/api` 를 **같은 오리진**으로 띄웁니다 — 실제 Pages 배포와
같은 구조입니다. 별도 서버를 미리 띄울 필요가 없습니다.
강의자료 다운로드 잠금까지 켠 가장 빡빡한 구성에서:

- 교육생이 가입해서 파일을 붙여 제출하고, 그 파일이 R2 에 실제로 올라가는지
- 제출물 화면에서 `/api/file/…` 이미지가 **실제로 렌더되는지** (naturalWidth 확인)
- 로그인하지 않은 브라우저가 파일 주소를 직접 열면 막히는지
- 다른 회원의 제출물이 목록·상세에서 보이지 않는지
- 삭제가 R2 파일까지 정리하는지
- 관리자가 회원을 정지시키면 그 사람의 열려 있던 화면이 로그인 안내로 바뀌는지

> 이 환경에는 Chromium 이 `/opt/pw-browsers/` 에 이미 있어서 그 경로를 직접 씁니다.
> 다른 곳에서 돌린다면 `browser.test.mjs` 의 `executablePath` 를 지우고
> `npx playwright install chromium` 을 한 번 실행하세요.
