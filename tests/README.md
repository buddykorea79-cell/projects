# 테스트

사이트를 고친 뒤 깨진 곳이 없는지 확인하는 회귀 테스트입니다. 배포에는 필요 없습니다.

```bash
cd tests
npm install
```

## 1. 구문 검사 — `npm run test:parse`

`assets/js/` 와 `worker/` 의 모든 파일을 ES 모듈로 파싱합니다. 브라우저를 띄우지 않아
가장 빠르고, 오타 하나로 사이트가 하얗게 뜨는 사고를 막아줍니다.

## 2. 회원 인증 — `npm run test:auth`

메모리 R2 스텁 위에서 **실제** `shared/auth.js` 와 `shared/r2api.js` 를 돌립니다.
브라우저 없이 서버 쪽 회원 기능만 집중해서 봅니다.

- 가입·중복 가입·대소문자가 다른 같은 이메일
- 로그인 실패 문구가 "계정이 있는지"를 흘리지 않는지
- 세션 쿠키가 HttpOnly · SameSite=Lax · Secure 인지, 위조 쿠키가 거부되는지
- 연속 실패 8회 뒤 잠기는지
- `ADMIN_EMAILS` 로 가입하면 관리자가 되는지
- 회원 명부(`members.json`)가 `/data/*` 로 절대 안 새는지
- 남의 업로드 폴더를 참조한 제출, 남의 제출물 수정·삭제가 막히는지
- 제출자 정보를 서버가 채우는지(클라이언트가 보낸 이름·이메일을 믿지 않는지)
- 비밀번호 변경·관리자 초기화·이용 정지 시 기존 세션 무효화
- 회원 삭제 — 정지되지 않은 회원·관리자·자기 자신은 거부되는지, 정지된 회원을
  지우면 명부와 세션이 함께 정리되고 제출물은 남는지, `purgeSubmissions` 를 주면
  제출물과 첨부 원본까지 지워지는지, 삭제한 이메일로 다시 가입되는지
- 임시 비밀번호 6자리(`/auth/forgot` 의 `method:'code'`) — 숫자 6자리가 그 자리에
  돌아오는지, 그 번호로 로그인하면 `mustChangePassword` 가 서는지, 새 비밀번호를
  정하면 번호가 죽는지, 30분이 지난 번호는 거부되는지, 5분 안의 재요청이 429 인지,
  없는 계정·정지된 계정에는 발급하지 않는지, `method` 를 주지 않으면 예전처럼
  `{ ok: true }` 만 돌아와 번호가 새지 않는지

## 2-2. 상호 투표 — `npm run test:vote`

메모리 R2 스텁 위에서 **실제** `shared/r2api.js` 를 돌려 투표 규칙과 회원 삭제를 봅니다.

- 투표를 켜면 비공개 프로젝트여도 서로의 제출물이 보이는지, 끄면 다시 닫히는지
- 표를 넣고 빼는 것이 집계·내 표에 반영되는지, 같은 곳에 두 번 넣어도 한 표인지
- 본인 제출물 투표 차단, 1인당 표 수 초과 거부
- 시작 전·마감 뒤에는 관리자도 넣을 수 없는지
- 득표수를 숨기면 진행중에 회원에게 집계가 **아예 안 내려가고**, 마감되면 공개되는지
- 제출물을 지우면 거기 들어간 표도 함께 사라져 투표자의 표가 되돌아오는지
- 회원을 지우면 그 사람이 넣은 표도 집계에서 함께 빠지는지
  (삭제 권한 규칙 자체는 위 2번이 봅니다)
- **마감 뒤 등록** — 마감일이 지나거나 접수를 닫은 과제에 회원은 등록할 수 없고
  관리자는 등록되며 `late` 가 붙는지, 그 제출물에는 표가 들어가지 않는지
  (없는 프로젝트는 관리자도 거부)
- **다른 회원 이름으로 등록** — 관리자만 되는지, 이름·기관을 요청이 아니라 **회원 명부**
  에서 가져오는지(위조 시도 무시), 가입하지 않은 이메일은 거부되는지,
  지정한 회원의 목록에 잡히고 `registeredBy` 가 남는지

## 2-3. 수강 현황 — `npm run test:attendance`

브라우저 없이 `assets/js/sheet.js` 와 `assets/js/attendance.js` 를 그대로 돌리고,
새 색인(`roster`·`attendance`)의 접근 권한만 메모리 R2 스텁으로 확인합니다.

- CSV — 따옴표 안의 쉼표·줄바꿈, 탭 구분, BOM, 엑셀이 저장한 EUC-KR
- XLSX — 만든 파일을 그대로 다시 읽기(한글·숫자·`<`·`&`·따옴표·빈 칸), 시트 두 장,
  확장자가 없어도 내용(zip 머리)으로 알아보기, 예전 `.xls` 안내
- Zoom 표시 이름에서 이름만 뽑기 — `부서명_이름`, 구분자 없이 붙은 이름,
  `홍길동의 iPhone`, `홍 길동`
- 동명이인 — 소속이 함께 적혀 있으면 자동으로 갈라내고, 없으면 물어볼 목록으로 남기기
- 명단을 다시 올려도 같은 사람은 id 를 지키는지, 빠진 사람의 출결이 함께 지워지는지
- 출석률·제출률의 분모가 "기록된 회차"뿐인지 (아직 안 한 회차를 결석으로 세지 않는지)
- 한 회차라도 결석·미제출이 겹친 학생만 "주의"로 잡히는지
- 내보내기 표의 열 구성과, 내보낸 엑셀을 되읽었을 때 같은 내용인지
- 일반 회원은 `/data/roster`·`/data/attendance` 를 **읽지도** 못하는지 (403)

## 2-4. AI Build Camp — `npm run test:camp`

메모리 R2 스텁 위에서 **실제** `shared/r2api.js` 와 `shared/camp.js` 를 돌립니다.

- 화면용 사본(`assets/js/camp.js`)과 서버용 사본(`shared/camp.js`)이 같은 것을
  내보내는지 — 두 벌로 둔 규칙이 어긋나면 여기서 잡힙니다
- 세 문항 만점이 20·10·10 이고 합계가 40점인지, 만점 밖 점수가 잘리는지
- 조는 1조~8조뿐이고 벗어난 값이 "미지정" 이 되는지
- 그룹장은 조가 있어야 성립하는지 — 조 없는 그룹장은 회원으로 내려가는지
- Build Camp 과제는 조 없이 제출되지 않고, 일반 과제에서는 조를 받지 않는지
- 그룹장이 **자기 조만** 보고, 그 조에서만 발표 과제를 뽑는지.
  그룹장에게도 남의 이메일은 가려지는지
- 한 조의 발표 과제가 하나로 유지되는지 — 다른 것을 뽑으면 먼저 것이 내려가고
  그 발표에 들어와 있던 점수가 함께 지워지는지
- 선정되지 않은 제출물·본인 발표·자기 조 발표에는 점수를 줄 수 없는지
- 같은 사람이 다시 주면 덮어쓰는지(줄이 하나로 유지)
- 평가 중에는 남의 점수가 안 내려가고 관리자에게는 보이는지,
  마감되면 모두에게 공개되는지
- 평균이 **채점한 사람 수**로 나뉘는지 (빈 칸을 0점으로 세지 않음)
- 평가 기간 전·마감 뒤에 점수와 선정 변경이 막히는지
- 원자료(`/scores/rows`)가 관리자에게만 열리는지
- 제출물·회원·프로젝트를 지우면 딸린 점수가 함께 사라지는지
- 발표 순서 추첨: 섞기가 원본을 건드리지 않고 모든 값이 모든 자리에 가는지,
  제출이 없는 조는 기다리지 않는지, 발표가 하나뿐이면 막히고 **둘이면 남은 조를
  기다리지 않고 열리는지**, 안 정해진 조를 두고 뽑으면 그 조가 순서에서 빠지고
  뒤늦게 정해질 때 어긋났다고 알리는지, 관리자만 뽑을 수 있는지, 뽑힌 순서가 모두에게 같게 보이는지, 다시 뽑으면 횟수가
  올라가고 줄은 하나로 유지되는지, 선정이 바뀌면 어긋났다고 알리는지,
  프로젝트를 지우면 추첨도 함께 사라지는지

## 3. R2 모드 통합 — `npm run test:r2`

메모리 R2 스텁 위에서 **실제** `shared/r2api.js` 와 **실제** `store/r2.js` 를 돌립니다.
Cloudflare 계정도 브라우저도 필요 없습니다. 확인하는 것:

- 색인 자동 생성, 한글 제목·파일명 왕복, 업로드 바이트 보존
- etag 조건부 쓰기 — etag 없이 쓰면 428, 낡은 etag 면 409 + 최신본 반환
- 동시 저장 3건이 서로를 덮어쓰지 않고 모두 반영되는지
- 제출물·프로젝트 삭제가 R2 파일까지 연쇄 정리하는지
- 경로 탈출·허용 폴더 밖 키·용량 초과·확장자·낯선 오리진 차단
- 업로드 파일에 `nosniff` 와 sandbox CSP 가 붙는지, SVG 가 인라인으로 열리지 않는지
- 강의자료 다운로드 토큰 — 발급·검증·위조·만료·다른 서명키 거부

## 4. GitHub 모드 통합 — `npm run test:github`

가짜 GitHub API 를 메모리에 만들고, **실제** `worker.js` 와 **실제** `store/github.js` 를
그 사이에 끼워 돌립니다. 브라우저도 네트워크도 필요 없습니다. 확인하는 것:

- 프로젝트·제출물 생성/수정/삭제가 올바른 경로에 커밋되는지
- 한글 제목과 파일명이 base64 왕복에서 깨지지 않는지
- 첨부 바이트가 그대로 보존되는지
- 동시 수정 충돌(409)이 나면 재시도로 복구되는지
- 프로젝트를 지우면 하위 제출물과 첨부까지 정리되는지
- 워커가 경로 탈출·허용 폴더 밖·과대 용량·낯선 출처를 막는지

## 5. 브라우저 종단간 (UI) — `npm run test:browser`

먼저 다른 터미널에서 사이트를 띄웁니다.

```bash
cd .. && python3 -m http.server 8899
```

그 다음 `npm run test:browser`. Chromium 을 띄워 실제 사람이 하는 순서대로
회원가입 → 로그인 → 제출 → 내 제출물 조회·수정 → 관리자(자동 승격) → 프로젝트 개설 →
회원 관리(정지·삭제) → 강의자료 → 소통방 → 과제 투표 → 비밀번호 변경까지 밟고,
폼 검증·404·아코디언·모바일 가로 스크롤·드로어까지 확인합니다. 로그인 전에는
홈·강의자료·내 제출물이 막히는지, 남의 제출물이 목록에 안 보이는지도 함께 봅니다.
상단 메뉴 순서(강의자료 → 소통방 → 과제 투표 → 내 제출물)도 여기서 지켜집니다.

이 묶음은 UI 흐름에 집중하려고 **브라우저 저장 모드로 고정**해 돌아갑니다.
그 모드의 회원 기능은 `store/demo-auth.js` 가 흉내내는 **시연용**이라,
진짜 인증 동작은 위 2번과 아래 6번이 봅니다.

## 6. 브라우저 종단간 (R2) — `npm run test:r2-browser`

R2 스텁 위에 사이트와 `/api` 를 **같은 오리진**으로 띄웁니다 — 실제 Pages 배포와
같은 구조입니다. 별도 서버를 미리 띄울 필요가 없습니다.
강의자료 다운로드 잠금까지 켠 가장 빡빡한 구성에서:

- 교육생이 가입해서 파일을 붙여 제출하고, 그 파일이 R2 에 실제로 올라가는지
- 제출물 화면에서 `/api/file/…` 이미지가 **실제로 렌더되는지** (naturalWidth 확인)
- 로그인하지 않은 브라우저가 파일 주소를 직접 열면 막히는지
- 다른 회원의 제출물이 목록·상세에서 보이지 않는지
- 삭제가 R2 파일까지 정리하는지
- 관리자가 회원을 정지시키면 그 사람의 열려 있던 화면이 로그인 안내로 바뀌는지
- 상단 `과제 투표` 메뉴로 투표 화면이 열리고, 표가 R2 에 남고 득표가 화면에 오르는지
- 남은 표가 없으면 버튼이 잠기고, 취소하면 되돌아오는지
- 투표자 이메일이 `/api/votes` 응답에 섞여 나오지 않는지
- 제출 현황이 제출자·미제출자를 갈라 보여주고 필터가 먹는지
- 정지된 회원이 목록 맨 아래로 내려가고, 삭제 버튼이 그 사람에게만 뜨는지,
  지우면 명부와 대시보드 회원 수에서 함께 빠지는지
- 비밀번호 찾기에 방법 두 가지가 뜨고(기본은 관리자 요청), `임시 비밀번호 즉시
  받기` 를 고르면 숫자 6자리가 화면에 바로 뜨는지 — 그 번호로 로그인하면 새
  비밀번호를 정하는 화면으로 데려가고, 정하고 나면 번호가 죽는지
- 상호 투표가 상단 메뉴에서 내려간 뒤에도 프로젝트 상세의 `투표하기` 와
  `#/vote` 주소로 그대로 열리는지

> 이 환경에는 Chromium 이 `/opt/pw-browsers/` 에 이미 있어서 그 경로를 직접 씁니다.
> 다른 곳에서 돌린다면 `browser.test.mjs` 의 `executablePath` 를 지우고
> `npx playwright install chromium` 을 한 번 실행하세요.

## 6-2. 수강 현황 브라우저 종단간 — `npm run test:attendance-browser`

R2 스텁 위에 사이트와 `/api` 를 같은 오리진으로 띄우고, 관리자가 하는 순서를
크로미움으로 그대로 밟습니다. 별도 서버를 미리 띄울 필요가 없습니다.

- 명단 CSV 를 올리면 이름·소속을 알아서 읽고 `data/roster.json` 에 남는지
- Zoom 접속기록을 올렸을 때 자동 매칭 수가 맞는지, 동명이인·명단에 없는 이름만
  팝업으로 물어보는지, 고른 대로 반영되고 새 학생이 명단에 들어가는지
- **출석을 반영해도 보고 있던 회차가 바뀌지 않는지** (이어 올린 제출자 파일이
  옆 회차로 새지 않도록)
- 파일 없이 체크박스로 고치고 저장하면 R2 에 그대로 남는지, 결석자 필터가 먹는지
- 오프라인 회차의 일자를 정하면 저장되는지
- 대시보드의 인원·기록된 회차·주의 학생, 학생 × 회차 표의 칸 수
- 학생을 검색해 고르면 8회차 이력이 열리고 주소에 남는지
- 내려받은 `.xlsx` 를 되읽어 출석·제출·미기록이 제자리에 있는지
- 일반 회원은 화면도 API 도 막히는지

## 6-3. 마감 뒤 등록 · 대신 등록 (UI) — `npm run test:late-browser`

규칙은 위 2-2 가 서버에서 봅니다. 여기서는 화면이 그대로 움직이는지 확인합니다 —
**투표판에서 빼는 일은 화면 쪽에서만 하므로 여기서만 잡힙니다.**

- 마감 뒤 회원의 제출 화면이 막히고, 관리자에게는 `관리자로 등록하기` 가 뜨는지
- 관리자 제출 화면이 "투표 대상에서 빠집니다" 를 미리 알려주는지
- 등록하면 R2 에 `late: true` 로 저장되고 상세에 `마감 후 등록` 배지가 붙는지
- 투표판에 기한 내 작품만 올라오고, 관리자에게는 몇 건이 빠졌는지 알려주는지
- 관리자 제출물 표에는 두 건 다 나오되 늦은 건의 득표 칸이 비는지
- 제출자 선택기가 관리자에게만 보이고, 고르면 위쪽 표시가 함께 바뀌는지
- 다른 회원 이름으로 등록하면 그 회원의 `내 제출물` 에 나타나는지

## 6-4. AI Build Camp 브라우저 종단간 — `npm run test:camp-browser`

서버 규칙은 `test:camp` 가 봅니다. 여기서는 R2 스텁 위에 사이트를 띄우고 실제
크로미움으로 **화면**이 그 규칙대로 움직이는지 밟습니다.

- 상단 메뉴에서 `과제 투표` 가 사라지고 `Build Camp` 가 그 자리에 있는지
- 프로젝트 개설 화면에 **과제 종류** 선택이 있고, 일반 과제에서는 발표 평가
  상자가 숨고 Build Camp 를 고르면 나타나는지
- 회원 관리의 **권한** 칸에서 `○조 그룹장` 으로 바꾸면 저장되고,
  `그룹장만` 필터로 걸러지는지
- 제출 폼에 1조~8조 선택이 뜨고, 고르지 않으면 제출이 막히는지.
  상세·`내 제출물` 에 조가 보이는지
- 그룹장에게 **우리 조만** 보이고 선정 버튼이 뜨는지, 일반 회원에게는 없는지,
  관리자는 다른 조도 뽑는지
- 평가 화면에 세 문항과 만점이 보이는지, 자기 조 발표에는 입력칸 대신 이유가 뜨는지
- 점수를 적으면 합계가 따라오고 만점 밖이 잘리는지, R2 에 실제로 남는지
- 평가 중에는 남의 점수가 안 보이고 관리자에게는 보이는지
- 결과 화면(관리자)에 순위·문항별 평균·채점 원자료가 모이는지,
  일반 회원은 들어갈 수 없는지
- 마감되면 입력칸이 사라지고 점수가 공개되며 선정도 바뀌지 않는지
- 발표 순서: 발표가 하나뿐이면 버튼이 없고 둘이 되면 **한 조가 비어 있어도**
  관리자에게 버튼이 열리는지, 빠지는 조를 미리 알려주고 누를 때 한 번 더 묻는지,
  뽑힌 순서에 그 조가 빠져 있는지, 누르면 연출이 돌며 자리가 하나씩 확정되고
  R2 에 남는지, 아직 안 본 사람에게는 순서와 순번을 감추고 `순서 확인하기` 만
  보여주는지, 한 번 본 뒤에는 다시 묻지 않는지, 평가 화면이 뽑힌 차례대로
  정렬되는지, 선정을 바꾸면 어긋났다고 알리는지, 다시 추첨하면 횟수가 오르는지
- 옛 `#/vote` 주소가 그대로 열리는지

## 7. 텔레그램 알림 · 재설정 버튼 — `npm run test:telegram`

메모리 R2 스텁 위에서 **실제** `shared/r2api.js` 와 `shared/telegram.js` 를 돌리고,
`global.fetch` 를 목으로 바꿔 텔레그램 서버로 나가는 호출만 가로챕니다. 실제
텔레그램 계정도 네트워크도 필요 없습니다.

- 환경변수(`TELEGRAM_BOT_TOKEN` 등)가 없으면 가입해도 텔레그램을 아예 호출하지
  않는지 — 알림이 꺼져 있어도 가입·제출·재설정 본 기능은 그대로 도는지
- 가입·과제 제출 알림에 이름·기관·프로젝트 제목이 담기는지
- 재설정 요청 알림에 `callback_data: "reset:<email>"` 버튼과 1회용 재설정
  링크가 붙는지, 쿨다운 안의 재요청은 알림이 다시 안 가는지, 가입하지 않은
  이메일은 알림 자체가 없는지(계정 존재를 흘리지 않음)
- 웹훅이 `X-Telegram-Bot-Api-Secret-Token` 이 없거나 틀리면 401 을 돌려주는지
- 허용된 채팅에서 버튼을 누르면 임시 비밀번호가 실제로 발급되고(그 비밀번호로
  로그인 성공), `answerCallbackQuery`·`editMessageText` 로 버튼이 사라지는지
- 다른 채팅 ID 에서 온 콜백은 거부되고 기존 비밀번호가 그대로 살아있는지
- 존재하지 않는 회원에 대한 콜백은 "찾을 수 없음" 알림으로 처리되는지
- 재설정 링크: 정책 미달 비밀번호(문자·숫자·특수문자 중 빠짐)는 거부되는지,
  링크로 정한 새 비밀번호로만 로그인되는지, 토큰이 1회용·60분 유효인지,
  임시 비밀번호를 발급하면 나가 있던 링크가 무효가 되는지
- 재설정 메일: 요청이 접수되면 신청자 이메일로 같은 링크가 발송되는지,
  쿨다운·미가입 이메일에는 메일이 안 가는지, 웹훅 변수가 없으면 조용히 꺼지는지
